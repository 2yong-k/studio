# Prompts, reference images and assets
Status: in use
Date: 2026-10-30

These are tips for writing the `prompt` and the reference images of generated elements. Tips per model are filled in only after actually comparing — do not invent and write down tips that have not been confirmed.

**Before writing a prompt, also read `<home>/lessons.md`** (`<home>` is the studio folder, the `home` from `studio doctor`). It holds the lessons from the user's own works (`references/review.md` §6), and it may not exist yet. Read it together with this file; where the two disagree, tell the user. New lessons go there, not here — this file ships with the plugin and every update replaces it.

## What a model receives
It is set by `slots` in `data/models.json`, the bundled model list in the plugin folder that SKILL.md names (read `models[]` there: each entry's `id` and `slots`).
- Image model: the prompt + reference images (`refs`, a minimum to maximum count per model). With `layoutRef: true`, one shape layout image takes up one reference image.
- Video model: the prompt + **one first frame** (the keyframe), and for a model with a last-frame slot (`wan-30`, `minimax-h3`, `seedance-25`), the last frame (`toFile`) too. There is no reference slot. So the face and style are decided in the keyframe, and the video `prompt` is written with the **motion**.
- Do not leave text to generation. Draw it with a `draw` element (`references/brief.md`).

## Tips per model
Each tip was confirmed by a comparison. The user's own new tips go to `<home>/lessons.md`, with the work folder and date that were compared as evidence.

### Image models
- **`gpt-25-flare` is the default.** In a one-image-each comparison with Sunburst using the same person prompt, the face and clothes came out sharper and the lighting more even. Sunburst's texture is rougher.
- **When continuing cuts with a person asset.** Put one person asset in `refs`, rewrite the person's features (age range, hair, clothes) in the prompt, and then add the sentence below. In all 3 cut keyframes (wide, medium, close-up), the face, hair and clothes held on the first attempt, and the background and lighting of the reference photo did not come along.
  > Use only his face, hair and clothing from the first reference photo; do not copy its gray background or white studio lighting.
- **When using a layout reference image (`layoutRef`).** When the sentence below was put at the very end of the prompt, none of the 5 keyframes drew the gray boxes and name tags.
  > The second reference image is only a rough layout guide for where things go; do not copy its gray boxes, dark background or labels.
- **`banana-pro` needs at least 1 reference image.** With none, the brief check refuses it (`BRIEF_INVALID`) before anything is sent. If there is no reference to use, fill it with `layoutRef: true`. A realistic selfie keyframe with only that guide picture also came out with no boxes or name tags.
- **When making a 3D anime avatar from a photorealistic picture of a fictional person as a reference (`banana-pro`).** With only "3D anime avatar … cel shading" written, a 2D webtoon picture came out, and it even followed the selfie arm and the composition of the reference photo. When the two points below were pinned down, a 3D render like a VRM model and a fixed front-facing camera came out (first attempt → second attempt).
  - Art style: "a three-dimensional CG render, not a 2D illustration or webtoon drawing", "3D hair modeled in glossy strands", "VRM model rendered in real time in Unity or Unreal Engine"
  - Composition: "do not copy its selfie pose, outstretched arm, camera angle, composition or photographic look"
  - The `happy-horse-11` video made from this keyframe felt more like 3D animation than a VTuber, though it was not bad. Motion-capture descriptions such as "slightly stiff and floaty" came out only weakly.
- **For a VTuber avatar, the character design decides the feel more than the art style does (`banana-pro`).** A plain avatar (straight brown hair, a knit top) made from a photorealistic picture of a fictional person as a reference was not VTuber-like and had few distinguishing features. When an original design with a clear concept was written with no reference photo (only `layoutRef: true`), the first image came out with the 2D Live2D art style and every feature written in the prompt. The video made from this keyframe came out well.
  - Art style: "a flat 2D anime illustration rigged as a Live2D model … clearly a drawn 2D illustration, not a 3D CG render and not a photo"
  - Design: symbols matching one concept were written one by one into the hair color (a two-tone), props (two hairpins, "clearly visible"), eyes (a color and highlights) and clothing (a pattern on it).
  - Pose: "standard Live2D idle pose: front view, upper body from the waist up … both arms relaxed down at her sides with her hands out of view". It makes it easy to pin the arms down in the video.

- **For a woodblock-print-like style such as silkscreen, `banana-pro` is better.** When the same subject was compared in three art styles, `gpt-25-flare` gave small, tame objects, and `banana-pro` gave thick ink lines and shadows.
- **When filling a flat picture all the way out with `banana-pro`.** When "the paper runs to the very edge" was written with "poster print", a picture of one vertical sheet of paper on a black background came out. When "poster" was removed and replaced with the sentence below, all four sides were filled. There were only two results, so it could not be told which wording was the cause. The same sentence filled all four sides on landscape 1376×768 cream paper too.
  > The coloured paper fills the entire image out to all four edges: no black backdrop, no dark margins, no mat, no sheet of paper lying on a surface.
  - In a risograph-style scene (portrait 768×1376, "risograph print … visible paper fiber" + two sticker draft images as references), even with this sentence ("The scene fills the entire image out to all four edges: no backdrop, no dark margins, no mat, no border, no frame, no cream die-cut sticker border and no sheet of paper lying on a surface"), three of the five came out as a picture printed on cream paper (margins of 14–45px). The dark scenes were not regenerated but cropped. The printed area was measured by the first ink (brightness under 140) met from the edge, and cropped to 9:16 at 4px inside. So generate a picture meant to fill the four sides at a resolution more generous than the delivery size, and put the subject inside, on the assumption that it will be cropped.
- **When writing the glow of a laptop screen in a dark room with `banana-pro`.** "the laptop screen adds a faint cool blue glow on his face from below" was barely visible on the face, and under the warm desk lamp light the grey hair came out golden-tinged. Even so, in the video "the screen light goes out" came out clearly (see the video model section below).
- **`banana-pro` draws bigger than the `layoutRef` box.** Even with "middle half of the image height" written for a 384px-high box, the objects and shadows came out 500–730px high. It also spreads into the empty space beside it. On a landscape image, three objects were put in boxes at 57–96% of the screen width and "The left half of the image is empty cream paper … sit inside the right half" was written, but they came out at 44–95% and invaded the place for the text on the left. If the background is an even picture, do not generate again; write `fit` (the rectangle the object goes into, the box in `references/brief.md`) on that box and fit it with `make` — it does not touch the generation fingerprint or approval, so it works at once on the received result. With `fit: [600, 56, 536, 518]` at the same position as in that first landscape image, the three objects came out 68px away from the text. A few lines at the edge of a generated picture differ from the paper color — one picture was dark, and in another the left 6 columns were bright and columns 7–12 were dark. `fit` took 16px off all four sides of the paper strip and joined it, and the seam was not visible even at 4× contrast.
- **Giving only one style reference makes the print tame (`banana-pro`).** When the same silkscreen sentence was given only one `style.png` and the layout guide, the black offset shadow and ink blotches were weaker and the lines cleaner than in the first landscape image, which added three object references. It was usable as it was. To make a matching set, first look at adding the final picture of the earlier work as a style reference (not confirmed). "its cap posted" (for a pen) was not followed and the cap was put down beside it.
- **Putting an earlier work's final picture in as an object reference carries the shape over as it is (`banana-pro`).** To five references (1 style · 3 objects · 1 layout guide), "The second, third and fourth reference images show <the three objects, each named> as they were printed before: keep each object's shape and details, but print them together on the cream paper and ignore their paper colours" was written. All three objects came out in the same shapes as the earlier pictures, on one sheet over the new paper color. A sentence allowing exactly four flat spot inks and naming the colors to leave out was also kept.
- **When leaving room for text on a thumbnail (`banana-pro`).** With the person put in the right half by `layoutRef` and "The left half of the frame is the dark room behind him: a bookshelf and a curtained window barely visible, softly out of focus, mostly deep shadow" written, the left half came out as a dark bookshelf and curtain. The bold white and yellow title drawn over it read well even with no band.
- **The middle state of an action is hard to catch in one picture (`banana-pro`).** "closing the lid … the lid is halfway down" was written, but a picture of a hand resting on an almost fully closed lid came out (the same work, a single result).
- **A picture that continues from another work, such as a video thumbnail, must state even the object's color.** When the laptop color was not written, a grey metallic laptop came out instead of the black laptop of the original video (the same work).
- **`banana-pro` makes the face older and the eyes narrower than the reference face.** Seen in two works: the grey hair and clothes were the same, but the face was a little older than the asset and the eyes were narrow. It was not to the point of looking like another person.

- **When making a sticker that needs a transparent background with `banana-pro`.** This model cannot output a transparent background. So it was generated on a gray backdrop with the sentence below and the background was cut out. All 4 came out as an even gray (RGB 169–181) with no black margin.
  > The sticker sits alone in the middle of a plain, flat, uniform mid-grey backdrop with nothing else on it: no texture, no surface, no paper sheet and no shadow on the backdrop.
  - Cutting out: fill and erase pixels close to the background color (distance 40) starting from the edge.
  - Gray border: the model draws a 1–3px gray border on the edge of the die line. When the mask was shrunk by 2px and only pixels that are gray and darker than the paper were erased up to 8px more, none was left even at 4× magnification.
  - No cutout tool ships with studio: write a short script for these steps, with the border-erase width in px as a parameter.
  - For an object with no die-line border, where the ink line is itself the outline (a folder), set the border-erase width to 0. When it was erased by 8, the dark gray ink line was caught by the "gray and darker than the paper" condition and the left and bottom outline disappeared. Even with 0, no gray border was left outside.
  - Size: these stickers stayed inside the `layoutRef` box (the opposite result to the line above).
  - An object with closed loops (a paper clip) keeps the grey inside its loops: cutting out from the edge clears only the ground outside the object. Plan a second pass that also erases the grey enclosed by the loops (84,195 px in that picture), or ask for the ground to show clearly through the loops (not tried).
- **Sticker look: flat poster print vs risograph (`banana-pro`).** The same microphone and pack were generated with two sentences and compared (the same work). Look B was kept for the set.
  - Look A ("flat poster print, die-cut sticker look, thick cream border, 1.5px dark ink outline, grainy ink texture …, no gloss"): clean lines and flat surfaces came out. Shrunk to hero size (about 130px), it looked like a code icon.
  - Look B (A's "flat poster print" changed to "risograph print with slight ink misregistration, visible paper fiber, halftone dot shading", and "no gloss" changed to "matte vinyl die-cut edge"): the halftone dots, plate misregistration and paper grain stayed even at the same size.
  - Pack: "a plain, empty rounded panel … left blank for a stamp" came out as an empty panel in both looks, with no text or logo.
- **Putting the two look-B drafts in as style references carries the look over (`banana-pro`).** The microphone and pack drafts were put in `refs`, and "copy their ink line weight, halftone dot shading, misregistration, paper fiber, cream die-cut border and two-color palette, but not their subjects" was written. All 7 stickers came out in look B, and the shapes of the microphone and pack did not mix in. The currency signs on them also came out correctly.
  - Look B's sentence has no "no gloss". So small gloss dots appeared on the round beads of one sticker.
- **"not any real console's controller" alone does not avoid a real pad (`banana-pro`).** When "d-pad, four face buttons, two thumbsticks" was written, a shape like a PlayStation pad came out. When the grips and sticks were removed and it was changed to "a smooth, low, rounded pebble … a plus-shaped d-pad … two big round buttons … nothing else", a shape unlike any game console came out (the same work, first attempt → second attempt). Avoid another company's product look not by a negative sentence but by removing that product's distinguishing features.
- **Fix a local defect of an earlier picture by putting that picture in as the first reference and writing only the place to fix, and draw it again (`banana-pro`).** A microphone whose grille holes ran together was put in as the first reference. When "keep its print style, shape, colours and cream border, but redraw the grille so that every slot is a separate, cleanly closed slot" was written, every hole closed separately, and the shape and look stayed as they were (the same work, first attempt).
- **If you ask to take one large part out of a reference picture, it is not taken out but drawn again (`banana-pro`).** A closed folder was put in as the first reference and "Draw the very same folder at exactly the same size and position … but with the kraft front cover taken away" was written. A closed folder with the kraft front cover still on came out again. The tab moved to the left and the proportions changed too, so "same size and position" was not kept either (second attempt of that work, $0.150 thrown away). A local edit like the line above works, but in an edit that takes a large part out, the reference picture wins. So do not put in as a reference a picture that holds the part to be removed. Write only the object to keep, add "There is no X … anywhere in the picture", and then align by the object box at delivery. When the closed-folder reference was removed and it was changed to "One flat <color> file-folder back panel on its own … There is no front cover, no pocket, no flap and no kraft or tan paper anywhere in the picture", a back panel in that color and two blank sheets came out with no kraft. The object box also differed from the closed folder's by 17px in width and 1px in height (second attempt). The word "folder" inside the prompt was also changed to "panel" — out of worry that "The whole folder is seen" might call up the whole folder again (the effect could not be told).
  - The one generated with no reference came out with a brighter accent color (the tab averages were up to 38 levels apart in one channel). It was matched by multiplying a per-channel gain onto only the pixels of that color.
- **To keep the contents inside a closed object, name its outer edges (`banana-pro`).** For a closed folder, "Nothing sticks out past the front cover" was written, but the sheets inside came out past the cover's right side (and a front cover cut out of that picture carried them along). Naming the edges kept them inside (second attempt):
  > the front cover is as wide as the whole folder, and its left, right and bottom edges are the folder's outer edges, with no paper, no sheet edges and no <color> showing past them on the left, right or bottom
- **A part that has fallen away is drawn even if you write it in the negative (`banana-pro`).** A closed pack and a torn-open pack were generated side by side in one picture. On the right pack, "Everything above the tear line is gone: the top seal band and the torn-off strip are not anywhere in the picture" was written. But the torn strip floated at a slant over the open pack, and a gray smoky blotch even appeared on one side of the opening. For the folder back panel above, "There is no X" worked, but there was no action there. If you write an action such as "torn open", it puts even the fallen piece into the scene. Make such a state from the closed picture with a script (see "Layers to be overlaid" below). The closed pack on the left and the body on the right of the same picture came out with the same window, band and size.
- **Layers to be overlaid, if generated separately, do not line up.** As with the folder just above, even when given the same reference and the same `layoutRef` box, the outline and the tab position differed. Some layers must match line for line when overlaid. For example, a pack body and a tear strip are the same width, 640, and the sawtooth line must match the top line of the body. Generate such layers as one whole picture and split it by script along the boundary line. Generate separately, and align by the object box, only a state that must be drawn anew (the inside of an open pack, an open folder).
  - The folder front panel was split from the closed folder by erasing above the top line of the front cover. It cannot be separated by color. The blank paper was almost the same color as the kraft. It cannot be separated by ink-line thickness either. The top line is 3–5px and the halftone dots are 3px, so they overlapped. For each column, going up from a fixed row inside the cover, the first place that meets ink (a line) running more than 6px horizontally or vertically was taken as the top line. For columns with a vertical line over 12px, the value of the neighboring column toward the center was used. A stair-stepped top line was also separated cleanly, and a 1–3px step remained only at the rounded corners.
  - For the pack, the line to split on was printed into the picture, and then split at the middle of that line. "one continuous dark ink zigzag tear line of small, even sawteeth runs straight across the whole front, about one sixth of the way down from the pack's top edge, just below the top seal band" was written. An even sawtooth line 6px thick came out across the whole width. But the height was 22% of the pack height, not 1/6 (17%). The band cell was fixed at the top 1/5 of the delivery cell, so when that line was matched, the pack was pushed toward the top of the cell (a 110px beam below). Writing the line higher than the place you want may help (not tried).
  - The way the line was found: inside the band, only ink (average brightness under 110) was given cost 0, and the minimum path from left to right was found (moving within 3 rows per column). Then the middle of the ink stroke was taken for each column. Columns that deviated more than 10px from the median were thrown away as the slanted side outline above the tear line. Without this filtering, thin spikes rose at both corners of the body. The two split pieces do not overlap in pixels, and with the band laid over the body it is exactly the closed pack. Both pieces have half of the line as an ink border.
  - The open state was made by throwing away the generated result (the 'part that has fallen away' line above) and drawing the opening behind the body by script. It consists of a back-wall sawtooth (the body's sawtooth raised by a lens-shaped amount, ink outline 5px), the cream paper inner face taken from the window, and an ink-colored depth below a smooth top line joining the sawtooth tips. The outline is the same as the body down to the pixel, so swapping it in does not stand out. It was usable as it was. At first the inner face was painted a shaded accent color, but it looked like a translucent band, so it was changed to cream.
  - The three (closed, back panel, front panel) were cropped and shrunk together by one object box of the closed folder. The back panel first stretched its own box to fit the closed folder box. When overlaid, it looked like one folder with no misalignment.
- **A color written for only one part spreads to the whole plate it is attached to (`banana-pro`).** "one rounded tab printed in <color>" was written, but the whole folder back panel with the tab came out in that color. The contrast with the kraft front cover came out well, so it was usable as it was. To keep the color to that part only, write the color of the rest of the plate too (not confirmed).
- **"cut into the paper" for a paper object becomes a printed line (`banana-pro`).** For a paper ticket, "where it meets each edge a small half-circle notch is cut into the paper" and "its edge is its own dark ink outline with no extra border" were written. But a picture came out with the ticket outline (the half-circle holes as lines curving inward) printed on a larger cream card, and about 25px of cream margin was left outside the ink line. The margin was cleared by script. A wall was built with the ink grown by 2px, and from the background the non-ink pixels were filled and erased. The gray band on the card's border was let through only for the first 4px, and finally only the piece connected to the center was kept. Then the holes were actually open. When "the paper itself is cut to this shape, with no card, sheet or margin around the outline" was added for the back of the card, it came out with no outer margin card. But "Its edge is its own 1.5px dark ink outline" was not kept. The outside was a cream border and the ink line was drawn inside it. So the cutout needed a border-erase width of 8 px.
- **A "very soft" pattern comes out strong (`banana-pro`).** For a foil panel, "a few very soft, wide diagonal bands of slightly lighter halftone" was written. But strong diagonal light bands and one fold mark came out. Stretched by the band ratio it looked like metal foil, so it was usable as it was. If an even texture is needed, leave the pattern sentence out entirely (not confirmed).
- **For a matching set, match not only the style sentence but the scene grammar (`banana-pro`).** The same look-B sentence was attached to five images of one set. Four were written as 'a dark scene + one beam of colored light coming down from above + one hero in the middle', and only one was written as 'a skyline and a moon-like coin under a cream sky'. That one stood out as the odd one. When it was rewritten with the same grammar (a dark desk, a coin with a symbol catching the light, a chart on the monitor behind), it looked like one set. In addition, it came out like this.
  - "embossed with one <sign>, and apart from that sign there is nothing written on it" came out as that sign in the two palette colors, not in the color the sign usually has as a logo.
  - "The main subject sits in the middle of the picture, between about one eighth and two thirds of the way down" was given together with a `layoutRef` box (12–66% of the height). In all six, the hero stayed above the bottom 28% (the place for the bottom panel). It was checked with a phone mockup (a picture with the panel places laid on by `drawbox`).
  - "drawn only as round glowing dots on short handles, with no hands, no arms and no faces" was added to "no people and no human figures or silhouettes". Then no people appeared in an audience scene either. But in a stage scene, a blurred round halftone mass appeared in the beam of light behind the main object. It looked like a distant audience (it was usable as it was).
- **Leave the logo place empty when generating and lay the real logo on (`banana-pro`).** The center badge sentence on the back of the card was changed to "The rays only begin outside a plain round area in the middle, about half the card's width across, which is left as flat dark ink with nothing in it: no badge, no shape, no outline, no circle line, no symbol." In one go, an empty ink-colored circle 52% of the card width came out with no border line, and the rays started around it. The circle was measured by walking from the center point in four directions to a pixel of the accent color (one channel over 150). The logo (a 512 px transparent picture) was laid on at about 83% of the circle diameter (190 of 230). Its dotted pattern did not blur even when shrunk by 0.37× (lanczos).
- **For a set of several images, generate one first.** Look at one with `generate --element <id>` and make the rest. A black-margin defect was caught at $0.150, and 7 images ($1.050) were not thrown away. For the sticker drafts too, the gray backdrop and border were first checked with one image. Putting a set in one work with several elements means one approval. Frame it as a collection sheet.
- **File size of a texture-heavy picture to be put on the web.** With Pillow `quantize(colors=128, method=FASTOCTREE, kmeans=4, dither=NONE)`, 1.4–1.9MB became 245–356KB, and the texture did not visibly decrease. `MEDIANCUT` at 64 colors is in the 600KB range, but the colors of small areas went wrong (a mustard coin turned olive), and a median filter erased the ink grain (the same work). If the system python has no Pillow, do it with ffmpeg — `-filter_complex "split[a][b];[a]palettegen=max_colors=128:reserve_transparent=0[p];[b][p]paletteuse=dither=none"` (a 1200×630 OG image 1.1MB → 444–455KB; in zsh, use braces like `${var}[p]`).

### Video models
- **`seedance-25` blocks a first frame with a realistic human face.** Even for a fictional person, the input filter refused it with HTTP 422 (`content_policy_violation`, resembling a real person). Do not choose this model for a video with a realistic person; pick another video model from the list.
- **In a selfie video, pin down the arm holding the phone.** When only "points at the window with an empty hand" was written, `happy-horse-11` gestured with the phone-holding arm, and for that 1 second the selfie arm vanished and only the camera floated (at 6–7 seconds). To include a gesture, write "the arm holding the phone stays stretched toward the camera to the end, and the gesture is only with the other hand over the table".
- **Live2D-style motion (`happy-horse-11`).** With "animated as a Live2D puppet, not as full animation … arms stay down … no 3D rotation, no camera movement, no zoom", the 2D art style and design held for the whole 6 seconds, and with the arms down only the head tilt, blinking and mouth shapes moved. But even though "no zoom" was written, the screen slowly approached and the face got a little bigger at the end.
- **Tie the time of an action to a line word rather than seconds (`happy-horse-11`).** When "at about 1.5 seconds" and "as he says 'this coffee'" were written together, the lines came out in two blocks (0.6–1.5 seconds, 2.1–3.2 seconds), and the cup was lifted at about 2.5 seconds, after "this coffee" came out. The model followed the word rather than the number. In a second work too, the lid in "As he says \"that's all\", he closes the laptop lid" was closed at 1.5–2.5 seconds, around when the line (0.6–1.6 seconds) ended. Assume it comes **after** the word, and match caption and action times by measuring the result.
- **Written as a fixed camera, like a phone propped up on a desk, it did not approach (`happy-horse-11`).** With "filmed by a phone propped up on the desk; the camera stays completely still" and "no zoom, no push-in, no camera movement", the distance stayed the same for the whole 6 seconds. In a selfie, it approached even with the same "no zoom" (the line above) — writing that it is a propped-up camera, not a hand-held camera, seems to work (a single result).
- **After an action with a large change of light, the face may change a little (`happy-horse-11`).** After the laptop was closed and the screen light went out, the face looked younger and rounder. It was not to the level of turning into another person. The light change overlapped with an action of leaning back in the chair, so the cause could not be told (the same work).
- **At the end of a selfie video, the arm may vanish (`happy-horse-11`).** Even though "the arm holding the phone stays stretched toward the camera to the end" and "no zoom, no push-in" were written, from 4.2 seconds of 5 the body came forward and the selfie arm left the screen (the same work). A sentence that prevents it has not been found yet. The cut length does not go into the generation fingerprint, so you can cut out that stretch by shortening only the cut.
- **25 Korean syllables in 6 seconds leaves room (`happy-horse-11`).** Two sentences of lines came out in two blocks, 0.4–2.9 seconds and 3.7–5.6 seconds. The caption times were matched by measuring the speech stretches with a 100ms-window RMS (the same work).
- **First frame = last frame makes a seamless loop (`wan-30`).** When the same picture was put in `fromFile` and `toFile` and "seamless loop … comes back to where it started" was written, the last and first frames of all five 3-second clips joined at SSIM 0.99. If you repeat it dropping one last frame, the same picture does not stand twice.
- **Even an object you wrote as "does not move" moves (`wan-30`).** A sentence naming two objects and saying they "do not move" was written, but one of them (a sleeve) opened and closed like a door midway, and the chart bars in "The chart … stay exactly as they are" rippled slightly. For an object that must stay still, it is worth trying to name it and write it as a property that cannot move, like "printed flat, like part of the paper" (not tested).
- **If the first and last pictures are different faces of one object, it spins the object (`wan-30`).** From the front of a closed folder → the back panel (two sheets of paper), "the front cover lifts up and flips away" was written, and instead of the cover opening, the whole folder spun on a vertical axis like a card in 0.15 seconds. "the folder never turns, tilts or spins" must be written together.
- **A video is redrawn at 720p, so the halftone is soft (`wan-30`).** Laid over the still picture, the position and color (within 1–2 steps) match, but at 1:1 magnification the halftone dots were smeared. Shrunk to 400KB per clip, it is softer still (the same two works).
- **For the motion of a still picture split into layers, recommend code motion first.** When the pack tear and folder opening were turned into video on "the same canvas as the still picture", the flying tear strip was cut off at the top edge of the canvas, and the quality was also lower than the approved picture, so code motion was used instead. When the requested picture is already split into layers like body, strip and cover, and the canvas is fixed, before generating compare code motion (original pixels, going off the canvas, exact axes) with video (deformation where the shape tears and crumples) and ask the user first. Video is better for motion that cannot be split into layers, like light and particles inside a picture (the same two works).

## When the model refuses
When the supplier blocks a request with an input filter, the attempt closes by itself as `settled`·`outcome: "refused"`. It is not a matter of checking the console or calling `resolve`.
- The reason is in `results[].reason` of the call that closed that attempt (`generate`, or `status` if it stayed in the sent state and then closed). An already-closed refusal also shows in `results[].cause` of the next `generate` (`LAST_ATTEMPT_FAILED`). If `content_policy_violation` shows, the model's filter blocked it.
- If `missing` or `value_error` shows, more often than not the bundled model entry (the input format) is wrong rather than the content. Fixing an entry of `data/models.json` is the plugin maintainer's job — do not edit it; tell the user, with the `reason`, so they can report it. Even after a fixed entry arrives in an update, only the model id goes into the fingerprint, so that element stays blocked: change the input or the model.
- The money is counted as gone (the estimated amount, the same rule as `provider_failed`). Tell the user with `usd`.
- The same input will be refused again and only the money goes out. `generate` with no element given skips that element with `LAST_ATTEMPT_FAILED`, and `--element` is blocked with `INPUT_REFUSED`. The only way is to change the input.
- Tell the user the reason, and ask, with a recommendation, whether to fix the prompt or keyframe or to pick another model. Either way the brief changes, so go through `preview` (if you changed the layout) → `estimate` → a new approval.
- For a known refusal (`seedance-25` blocking a realistic face), follow the line under "Video models" above.
- A 422 whose shape differs from the docs, or that points at the request itself, is not closed and stays `sent`, coming out as `PROVIDER_ERROR`. Then follow `status` and `references/recovery.md`.

## Reference images
- In `refs`, write an image under `assets/…` or inside this work folder. The count must be within the model slot limit (`BRIEF_INVALID`).
- Use `layoutRef` only for image generation (keyframes included). Putting shapes into the first frame of a video model only makes the shapes move, so it is not used on a video element.
- **The only files that leave your machine are `refs`, the layout reference image, the first frame of a video (a generated keyframe or a `fromFile` picture) and the last frame (a `toFile` picture).** These files are uploaded to the generation service and then to the model supplier. `composite` and `capture` files and other work folder files do not leave. To put the user's photo or private material into `refs`, `fromFile` or `toFile`, first tell the user and get confirmation. At the last check, the supplier's documentation gave no retention period for uploaded files; say so if the user asks.

## How to use assets
An asset is material reused across several works. How to make one is "Making assets" in `SKILL.md`. In the brief, say that you write the folder in `assets` to use it (the file must actually exist), and point at the file from the element.
- **Hero sheet** — a reference image that keeps the same person continuous across works. Put it in `refs` of an image generation element that has the person (for example `assets/hero/sheet.png`). If you made a new person and it seems it will be used again, ask the user whether to keep it as a sheet.
- **Style sentence** — text that fixes a work's mood in a sentence or two (a description file inside `assets/<name>/`). It is not read by code; Claude reads it and copies it into `prompt` as it is.
- **Brand kit** — logos and colors. A logo file is **laid on as it is** with a `composite` element (do not redraw it by generation — the text and mark go off). Write a brand color with the same value in the `color` of `draw` and in the prompt.
- Fonts and music can be used only if there is a commercial-use license in `asset.json` (hard rule 5).

## Real people and prohibitions (hard rule 6)
- A **real person** is made to resemble when the user gives a photo and the user confirms that the person consented (the user included). If it is someone used for the first time, ask once, put the photo in `assets/<name>/`, and write "Consent confirmed: YYYY-MM-DD" in the README. The model does not know the person by name, so do not write the name in the prompt; make the likeness with the photo (`refs`).
- Do not make it even with consent — a famous person or public figure whose consent cannot be confirmed (making it look like an ad model or an endorsement), sexual or insulting scenes, and scenes that make it look as if the person really said words they did not say.
- Do not use or imitate **another party's brand** logo, trademark, product look or trade dress. The only exception is **a brand the user owns**.
- Do not make **false scenes** that look like fact — a fake event that looks like a news, evidence or on-site photo, or a scene that looks like a record of something that did not happen.
- If a request runs into this, do not make it; tell the user the reason and propose an alternative (a fictional person or brand, a scene that is clearly staged).
- In review (`references/review.md`) too, check whether the result came out resembling a real person whose consent was not confirmed or another party's brand. If it resembles one, do not use that result and tell the user.
